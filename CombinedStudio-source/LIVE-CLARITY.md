# Live rolling clarity preview

The complete app is published to `outputs/FramePilot-VelvetAudio-LiveClarity/`. Motion Clarity offers a captured-content preview, with `LiveClarityLab.html` shipped beside the executable. `Open Live Clarity.cmd` opens it in the default browser. The prior stable desktop shortcut is retained.

This prototype uses browser getDisplayMedia to obtain a user-selected video-only stream. No audio, server transmission, recording, injection, driver changes or monitor settings are involved. Selection is performed in the browser's capture picker. The in-app browser's capture picker was not observable through browser automation; real source selection requires user input. Chrome/Edge can be used if the in-app browser does not display a picker.

Both sides display the same captured video. The left is unchanged; the right displays staggered bands for one modeled refresh per pulse cycle. The pulse effect is initially off and stops on focus loss, visibility changes, source end, Escape, inconsistent timing or explicit Stop. Stop cancels the frame callback, ends all stream tracks and clears the buffered image. Video frames are copied to an internal canvas capped at 1280 pixels wide. This cap and screen capture can lower detail and add latency. It is an experimental preview, not a game overlay.

The output timing gate requires animation cadence within 3% of selected output Hz, p95 interval below 1.5 nominal intervals, at least 20 incoming frame intervals, incoming FPS at least 95% of outputHz/ratio, and a recent video frame. At output 480 Hz and ratio 8 the target input is 60 FPS. Ratio 4 requires 120 FPS. This prevents presenting repeated 60 FPS captures as valid 120 FPS pulse content. The gate does not measure actual scanout or source-to-photon latency.

Validation: Release publish passed with the existing SteamArtwork obsolete API warning. The integrated browser pipeline self-test ran using a synthetic 60fps canvas stream: incoming frames measured 60.0fps and output callbacks 480.0fps; ratio 8 enabled D, ratio 4 rejected D, and Stop released the stream and disabled D. This self-test is explicitly labeled synthetic. The user subsequently selected a real TestUFO capture: incoming frames measured about 118–120fps, output callbacks about 478–480fps. The selected CRT source was switched to normal UFO motion and Standard RGB to avoid stacking effects; its prior URL is saved in `outputs/LiveClarity-validation/saved-crt-reference-url.txt`. D enabled at ratio 4 and accepted the timing gate. Evidence is in `outputs/LiveClarity-validation/live-ufo-D.png` and `live-ufo-timing.txt`. The complete app's 73 UI checks and 22 motion checks passed. Physical clarity and game latency were not measured. The earlier lab's self-reported preference for D motivates the test; it is not evidence of a competitive benefit from capture.

For first testing, select normal TestUFO rather than its CRT shader to avoid applying effects twice. Compare the unchanged capture and D under the same source stream. Keep the real source visible so it continues producing frames. Capturing and fullscreen-previewing the same entire monitor can create feedback; select a specific source tab/window and do not choose this preview itself.
